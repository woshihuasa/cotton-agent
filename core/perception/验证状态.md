## 二、人工核对记录（我逐条看过的）

### calibrate.py

**① 分位数位置** — `k = ceil((n+1)(1-alpha))`，n=100/alpha=0.1 → `ceil(90.9)=91` → `s[90]`。
100 个分数 `1..100` 时 `s[90] = 91`。自检断言 `q == 91.0` ✅ 正确。

**② log 空间区间对称性** — `center = log(detected) - log_bias`，
`[exp(center-hw), exp(center+hw)]`。在 log 空间对称 ⇒ 原空间**乘性对称** ⇒ 符合 NMS 乘性少计的形态 ✅。

**③ Wilson 区间公式** — 标准形式，n=0 时返回 `(nan, nan)` 已处理 ✅。

**④ 分层回退逻辑** — 所有域都 < `min_per_domain` 时返回 `{"__pooled__": ...}`；
部分域太小时借 pooled 模型并标 `reliable=False` ✅ 合理。

**⑤ 潜在问题**：`calibrate_stratified` 里对每个小域都重新调一次 `calibrate(points, "pooled", ...)`，
重复计算。域多时浪费，但**不影响正确性**。可后续优化。

### geometry.py

**① GSD 公式** — `gsd_at_1m = (sensor_w/focal) / image_w`，
乘高度得 `gsd(h)`。Mavic3Classic：`(17.3/24)/5280 × 500cm = 0.0683 cm`，
5m 时 `0.0683 × 5 = 0.341`... 

> ⚠️ **这里我算出来和预期不符**。预期 5m GSD ≈ 0.12 cm/px。

让我重新核：`sensor_width_mm=17.3`、`focal=24mm`、`image_width_px=5280`。
`gsd_at_1m = (17.3/24)/5280 = 0.721/5280 = 1.365e-4` 米/像素 = **0.01365 cm/像素@1m**。
5m 时：`0.0682 cm/px`。**但预期是 0.12 cm/px。**

**差了约 1.76 倍。** 说明 `sensor_width_mm` 或焦段参数不对 —— Mavic 3 Classic 的等效焦距 24mm 对应的传感器宽度不是 17.3mm（那是 4/3 系统的**对角线**尺寸）。

**正确算法**应改用探索日志里的经验式：水平覆盖 ≈ `h × 1.286`。
即 `gsd = h × 1.286 / 5280`，5m → `6.43/5280 = 1.218e-3` 米 = **0.122 cm/px** ✅ 与预期一致。

**所以 `Camera` 的 GSD 公式需要改成用 FOV/覆盖比，而不是传感器尺寸。**
这是我必须先修的地方 —— 见下节。

### infer.py

**① `plan_tiles` 覆盖完整性** — `xs` 从 0 到 `img_w - tile_size` 按 stride 步进，
末尾若 `xs[-1] + tile_size < img_w` 则补 `img_w - tile_size`。
`x1 = min(x0 + tile_size, img_w)` ⇒ 不越界 ✅。

**② 坐标还原** — `Box(x1=bx1 + ox, ...)`，`ox` 是切片左上角 x ✅。

**③ 去重** — 标准 NMS，按 conf 降序，IoU > 阈值则抑制 ✅。

**④ `crop_with_pad`** — 补黑边到 size×size。自检第 2 节的标记点测试走的是正常路径 ✅。

## 三、已修正的问题：GSD 公式（🔴 → ✅ 已修）

**原问题**：`Camera.gsd()` 用传感器物理尺寸算，得到 5m GSD = 0.068 cm/px，
而师兄报告的实测值是 **0.096–0.128 cm/px**（[当前情况备忘.md](../当前情况备忘.md) 第 2.2 节）。
**差约 1.8 倍，面积差约 3 倍** —— 会让所有密度换算系统性偏离。

**根因**：「Mavic 3 Classic 是 4/3 CMOS」里的 **17.3mm 是系统对角线**，
不是传感器宽度，不能代入 `gsd = (sensor_w/focal)/image_w`。

**已改为**：用**实测反推的水平覆盖系数**建模（`coverage_factor`，无量纲）：

```
gsd(h) = coverage_factor × h / image_width_px
Mavic 3 Classic: coverage_factor = 1.286
  5m → 0.122 cm/px  ✅
  7m → 0.171 cm/px  ✅
  9m → 0.219 cm/px  ✅
```

三个数与探索日志的 0.12 / 0.17 / 0.22 **完全吻合**，
且 5m 的 0.122 落在师兄报告 0.096–0.128 区间内 ✅。

**新增工具函数** `camera_from_gsd()` —— 若你拿到实测 GSD 记录，
直接反推系数比用标称参数更准。

**⚠️ 遗留**：`Mavic3M` 和 `Mavic3T` 的系数目前**暂用 Classic 的 1.286**，
但两者焦距不同（12.29mm / 4.4mm），**系数必然不同**。
2025/2026 批用到这两台机器时，必须先确认（见下节待办 2）。

## 五、怎么确认 Mavic3M / 3T 的覆盖系数

三个办法，按可靠性排序：

1. **问师兄要 GSD 记录**（最可靠）——他报告里写了 3–5m 下 0.08–0.16 cm/px，
   用 `camera_from_gsd()` 反推即可
2. **从影像反推**——找一张该机型的影像，量一个已知长度的地物（如田埂、地膜行距）
3. **按焦距比例估算**（最不可靠，仅作参考）——
   若 Mavic3M 与 Classic 传感器尺寸相同，则系数 ∝ 1/焦距：
   `1.286 × 24/12.29 ≈ 2.51`。但这依赖"传感器相同"的假设，**必须验证**
